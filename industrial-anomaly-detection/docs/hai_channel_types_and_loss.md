# HAI 20.07: типы каналов и функция потерь

Источник: официальный `hai_dataset_technical_details.pdf`, версия 4.0, май 2023; таблица HAI DATA POINTS, печатные страницы 12–15 (страницы PDF 13–16). Локальная копия находится в `docs/references/`. Источник: https://github.com/icsdataset/hai/blob/master/hai_dataset_technical_details.pdf

## Типы

Для 59 признаков HAI 20.07: 55 числовых и 4 булевых. Нельзя назначать тип только по dtype, числу уникальных значений или ступенчатой форме сигнала.

|---|---|---|
| P2_Auto, P2_Emgy, P2_On, P2_TripEx | Кнопки/переключатели, Boolean 0/1 | На входе 0/1 без StandardScaler; на выходе 2 logits на канал, CE |
| P1_B2004, B2016, B3004, B3005, B4002, B400B, B4022 (с префиксом P1_) | Физические уставки/требуемые значения давления, уровня, расхода, температуры | Числовые, StandardScaler по train и MSE |

## Loss и score

Новая модель имеет две головы: `[B,55]` для числовых прогнозов и `[B,4,2]` для logits булевых каналов. Обе прогнозируют состояние t только по истории до t. Не подавать целевое x[t] в прогнозирующий вход.

Для каждой записи: `numeric_error = mean((numeric_pred - numeric_target_scaled)^2)` по 55 каналам; `binary_error = mean(CE(binary_logits[j], binary_target[j]))` по 4 каналам. `score = numeric_error + binary_error`; обучающий `loss = mean(score)` по batch. Это начальный выбор весов 1:1 по группам, соответствующий ТЗ, а не универсально оптимальная настройка. Если меняются веса, подбор только по train/validation с новой калибровкой.

CE получает raw logits и long targets, softmax перед CE не применяется. Для двух классов альтернативный BCEWithLogitsLoss с одним logit математически подходит, но в реализации выбрана двухклассовая CE для единого контракта категориальных устройств.

StandardScaler обучается только на 55 числовых train-каналах. Булевы состояния сохраняются 0/1; известные по документации классы {0,1} задаются даже если в train встречается один. Константные числовые каналы не удаляются автоматически. Пропуски требуют масок и нормировки по доступным целям; текущая функция намеренно принимает только уже проверенные полные HAI-данные.

Изменение типов/голов/loss требует нового preprocessing, обучения, checkpoint и порога. Прежние scaler/model/threshold относятся к numeric smoke baseline и не совместимы с mixed-моделью. Score является ошибкой прогноза, не вероятностью атаки. Порог задаётся по нормальной validation после выбора checkpoint; test не используется при настройке.

## Всплеск 2019-09-15 07:00:00

P4_ST_PS — уставка мощности, поэтому переход 50→0 не означает переключение бинарного флага. Одновременное отклонение частоты P4_ST_FD и изменение мощности P4_ST_PO совместимы с реакцией на изменение уставки, но точная причина конкретного эпизода не подтверждена журналом событий. Таблица указывает диапазон P4_ST_FD [-0.02,0.02], а наблюдение около -0.0506 выходит за него: регистрировать как расхождение с описанием, не обрезать автоматически. Замена четырёх Boolean-каналов на CE сама по себе не устранит этот числовой всплеск.

MSE оставляется базовым вариантом по ТЗ. Huber или иная нормировка может исследоваться отдельной абляцией, но способна снизить чувствительность к атакам, создающим большие ошибки. Нельзя выбирать её только ради удаления одной ложной тревоги. Перед обучением полезен persistence-baseline x_hat[t]=x[t-1], оценённый на тех же validation-целях.
